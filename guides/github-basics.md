# GitHub basics

GitHub нужен не только программистам. Для работы с агентом это страховка: если проект сломался, можно вернуться к рабочей версии.

## Что такое репозиторий

Репозиторий - это папка проекта с историей изменений.

Внутри может быть:

- код;
- README;
- инструкции;
- шаблоны;
- документация;
- настройки без секретов.

## Приватный или публичный

Для личных проектов и учебных заданий начинайте с приватного репозитория.

Публичный репозиторий видят все. Не публикуйте туда:

- `.env`;
- токены;
- клиентские данные;
- личные документы;
- приватные ссылки;
- raw-чаты.

## Минимальный цикл

После каждого рабочего шага:

1. Проверили, что проект работает.
2. Проверили, что секреты не попали в файлы.
3. Сделали commit.
4. Запушили в GitHub.

Так появляется точка возврата.

## Что попросить у агента

```text
создай приватный GitHub-репозиторий для этой папки. перед первым commit проверь, что нет .env, токенов, ключей и приватных данных. добавь .gitignore и README.md.
```

Если GitHub уже создан:

```text
проверь статус git, покажи какие файлы изменены, проверь секреты, предложи commit message и только после моего подтверждения сделай commit.
```

## `.gitignore`

Минимальный `.gitignore`:

```gitignore
.env
.env.local
.DS_Store
node_modules/
dist/
build/
.cache/
```

Добавляйте туда всё, что не должно попадать в GitHub.

## Как откатиться

Если после изменений всё сломалось:

```text
посмотри историю git, найди последний рабочий commit и объясни, как безопасно откатиться. ничего не откатывай без моего подтверждения.
```

Важно: откат - нормальный рабочий инструмент. Это не провал.

## Хорошая привычка

Новая задача - новый чат. Рабочий результат - commit. Большое изменение - сначала план, потом реализация.
