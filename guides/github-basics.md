# GitHub basics

Этот гайд про GitHub в режиме "всё делает агент". Человек не учит команды, не копирует их в терминал и не собирает репозиторий руками. Человек формулирует задачу, задаёт правила безопасности и проверяет результат.

GitHub нужен как история версий и точка возврата. Если агент сделал полезное изменение, оно должно быстро попасть в commit и push. Если агент ошибся, можно посмотреть diff, откатиться или передать проект другому агенту.

## Что поручить агенту

Для новой папки:

```text
подготовь эту папку к GitHub. проверь, что внутри нет секретов, токенов, `.env`, приватных данных и лишних артефактов. добавь `.gitignore` и README.md, если их не хватает. создай приватный GitHub-репозиторий, сделай первый commit и push. если не хватает авторизации или доступа, остановись и скажи, что именно нужно подключить.
```

Для папки, где Git уже есть:

```text
проверь git status и diff, найди рискованные файлы и секреты, запусти доступные проверки, сделай commit с понятным сообщением и push. после push покажи commit hash и состояние рабочей папки.
```

Если вы заранее решили пушить каждое изменение сразу, скажите агенту это явно:

```text
в этом репозитории после каждого законченного изменения сразу делай commit и push. перед push проверяй diff и секреты. если видишь риск удаления данных, миграций, ключей или приватных файлов - остановись и спроси.
```

## Что агент должен проверить

Перед commit агент проверяет:

- какие файлы изменены;
- нет ли `.env`, ключей, токенов, дампов, личных данных и больших временных файлов;
- есть ли `.gitignore`;
- запускаются ли тесты или сборка, если они есть;
- не удалены ли важные файлы случайно;
- commit message описывает реальное изменение.

Человек не обязан смотреть каждую команду. Достаточно попросить агента в конце показать краткий итог: что изменено, что проверено, что запушено.

## `.gitignore`

Попросите агента собрать `.gitignore` под конкретный проект:

```text
обнови `.gitignore` под этот проект. учти язык, фреймворк, локальные env-файлы, артефакты сборки, кэш, системные файлы и всё, что не должно попасть в GitHub. не удаляй файлы без отдельного подтверждения.
```

Обычно там должны быть:

```gitignore
.env
.env.*
!.env.example
.DS_Store
node_modules/
dist/
build/
.cache/
```

## Как откатываться

Откат тоже отдавайте агенту, но с запретом на немедленное действие:

```text
найди последний рабочий commit, объясни что изменилось после него и предложи безопасный план отката. ничего не откатывай и не удаляй без моего подтверждения.
```

Откат - обычный рабочий инструмент. Главное не просить агента "просто починить всё" вслепую, а сначала посмотреть историю и diff.

## Хорошая привычка

Новая задача - короткое описание для агента. Законченное изменение - commit и push. Сомнительное действие - сначала план и подтверждение.
