# Claude Code как рабочая среда

Claude Code, Codex и Cursor можно использовать не только для кода. Это рабочая среда, где агент читает файлы, помнит правила проекта, помогает вести задачи, созвоны, тексты и исследования.

Ниже базовая архитектура, которую можно адаптировать под себя.

## Идея

Не пытайтесь держать всё в одном длинном чате. Делайте память в файлах.

Минимальная структура:

```text
my-ai-workspace/
  README.md
  CLAUDE.md
  notes/
  daily-logs/
  meetings/
  projects/
  skills/
```

Что за что отвечает:

- `README.md` - что это за workspace и где что лежит;
- `CLAUDE.md` - как агенту с вами работать;
- `notes/` - важные заметки;
- `daily-logs/` - логи дней;
- `meetings/` - созвоны и summary;
- `projects/` - отдельные проекты;
- `skills/` - повторяемые команды.

## Первый `CLAUDE.md`

Скопируйте `templates/claude-md-starter.md` и заполните под себя.

Минимум:

```markdown
# Рабочие правила

## Кто я

[имя, роль, чем занимаюсь]

## Как со мной общаться

- отвечай на русском;
- пиши коротко;
- если задача неясна, сначала задай вопросы;
- перед изменением файлов дай план;
- не трогай секреты и `.env`;
- не пушь в GitHub без проверки.

## Где что лежит

- `daily-logs/` - логи дней;
- `meetings/` - созвоны;
- `projects/` - проекты;
- `skills/` - команды.
```

## Slash-команды и skills

Скилл - это повторяемая инструкция для агента. Например:

- `skills/daily.md` - собрать фокус дня;
- `skills/meeting.md` - сделать summary созвона;
- `skills/tasks.md` - вытащить задачи из текста;
- `skills/research.md` - провести ресёрч.

В простом варианте можно не устанавливать ничего особенного. Просто откройте файл, скопируйте текст и вставьте агенту.

## Ежедневный цикл

Утром:

```text
используй skills/daily.md. помоги собрать фокус дня. прочитай последние 3 файла из daily-logs, если они есть.
```

Днём:

```text
вот апдейт по дню. обнови лог и подсвети, что поменялось в фокусе.
```

Вечером:

```text
собери короткое summary дня: что сделал, что застряло, что перенести завтра.
```

## Созвоны

После встречи сохраните транскрипт или заметки в `meetings/raw/`, затем попросите:

```text
используй skills/meeting.md. сделай summary созвона: цель, решения, задачи, открытые вопросы.
```

Хороший результат:

- есть список решений;
- у задач есть owner;
- открытые вопросы отделены от задач;
- ничего не выдумано.

## Память

Если агент узнал что-то важное, не надейтесь, что он сам запомнит.

Пишите:

```text
запиши это в подходящий файл памяти и обнови README, если нужно.
```

Раз в неделю просите:

```text
прочитай daily-logs и meetings за неделю. собери weekly-review.md: главные решения, незакрытые задачи, повторяющиеся проблемы.
```

## MCP и внешние сервисы

MCP подключает агента к внешним сервисам: Telegram, календарь, Figma, базы данных, Google Drive.

Не подключайте всё сразу. Начинайте с одного сервиса и read-only режима.

Перед действием, которое меняет внешний мир, требуйте подтверждение:

```text
не отправляй сообщения, не удаляй файлы и не меняй данные без моего явного подтверждения.
```

## Хороший первый проект

Соберите маленький workspace:

1. Создайте папку `my-ai-workspace`.
2. Добавьте `README.md`.
3. Добавьте `CLAUDE.md`.
4. Скопируйте 2-3 skills из этого репозитория.
5. Проведите первый daily.

Не начинайте с автоматизаций. Сначала добейтесь, чтобы агент уверенно понимал вашу папку и правила.
