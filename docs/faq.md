# FAQ

## Что поставить на старте?

Вам нужен один агент на выбор: Codex, Claude Code или Cursor. Любой подходит для практики.

Минимум:

- один чат: ChatGPT, Claude или другой удобный;
- один агент: Codex, Claude Code или Cursor;
- GitHub-аккаунт;
- отдельная рабочая папка на компьютере.

Для билдерских заданий позже пригодятся Railway, Supabase, Telegram BotFather, Pencil или Figma. Но не ставьте всё в первый день.

## Что выбрать: Codex, Claude Code или Cursor?

Если у вас уже есть платный ChatGPT - начните с Codex.

Если у вас уже есть Claude - начните с Claude Code.

Если вам удобнее работать в редакторе кода или другие варианты плохо доступны - используйте Cursor.

Смысл потока не в конкретной кнопке конкретного продукта. Важнее научиться ставить задачу агенту, проверять результат, сохранять версии и двигаться маленькими итерациями.

## Чем чат отличается от агента?

Чат отвечает текстом. Он помогает думать, но обычно не работает с вашим компьютером.

Агент работает в папке проекта: читает файлы, пишет код, запускает команды, делает коммиты, тестирует.

Если модель просит вас "создать файл руками", скорее всего вы в чате. Если модель сама создаёт файл - вы в агенте.

## Что делать, если инструмент не ставится?

Не застревайте на одном инструменте.

Если не ставится Codex - попробуйте Cursor или Claude Code.

Если не работает Claude Code - попробуйте Codex или Cursor.

Если старый Mac или Windows создают проблемы, проще сменить инструмент, чем тратить дни на установку.

## Нужен ли терминал?

Терминал - это текстовый способ управлять компьютером. Агенты часто используют его сами, потому что через команды удобно запускать проекты, тесты, Git и деплой.

На старте не нужно становиться специалистом по терминалу. Достаточно понимать:

- агент обычно сам выполняет команды внутри открытой рабочей папки;
- вы можете попросить объяснить простыми словами, что он сделал;
- если хочется больше контроля, попросите сначала показать план действий.

## Безопасно ли давать агенту доступ к файлам?

Да, если работать в папке, которую вы сами создали под проект.

Хорошая практика:

- создайте отдельную рабочую папку под проект;
- откройте агента только в этой папке;
- сохраняйте рабочие файлы в GitHub, чтобы ничего не потерялось;
- не просите агента удалять что-то за пределами рабочей папки;
- перед публикацией попросите агента проверить секреты.

Пока вы сами не просите о таком действии, агент не будет удалять файлы вне проекта. Отдельная папка делает границы понятными и безопасными для старта.

Подробнее: `docs/safety-and-secrets.md`.

## Где хранить код?

В GitHub.

После каждого рабочего шага делайте checkpoint:

- всё работает локально;
- секреты не попали в код;
- есть commit;
- если проект опубликован, деплой тоже работает.

GitHub нужен не только "для программистов". Это страховка: если агент сломает проект, можно откатиться.

## Когда начинать новый чат?

Начинайте новый чат, когда:

- агент начал путаться;
- задача поменялась;
- разговор стал длинным;
- вы переходите от планирования к реализации;
- нужно сделать новый независимый шаг.

Перед новым чатом можно попросить:

```text
собери короткий handoff для следующего чата: что мы делали, что уже работает, какие файлы важны, что делать дальше.
```

## Как работает память агента?

Не надейтесь, что агент "сам всё помнит" между чатами.

Надёжная память - это файлы, которые вы формируете сами. Ниже только один пример того, как это может выглядеть:

- `README.md` - что это за проект;
- файл правил агента - например `AGENTS.md` или `CLAUDE.md`;
- `notes/` - заметки;
- `logs/` - дневники или итоги;
- `decisions.md` - принятые решения.

Можно выбрать другую структуру: один общий файл, папку `notes/`, папку `projects/`, отдельные правила или дневник решений. Если хотите, чтобы агент что-то помнил, попросите записать это в файл.

## Что такое MCP?

MCP - это способ подключить агента к внешнему сервису: Telegram, Figma, Google Drive, базе данных, календарю и так далее.

Начинайте с read-only интеграций. Действия вроде "отправить сообщение", "удалить письмо", "изменить базу" должны требовать явного подтверждения.

## Нужно ли сразу подключать Supabase, Railway и OpenClaw?

Нет.

Supabase нужен, когда появляется база данных или авторизация.

Railway нужен, когда проект должен работать в интернете, а не только на вашем компьютере.

OpenClaw нужен, если вы хотите личного ассистента в Telegram, который живёт на сервере. Это не обязательный стартовый шаг.

## Как не утонуть?

Выберите один маршрут и один инструмент.

На старте хорошая цель - не "освоить весь AI", а сделать одну маленькую работающую штуку:

- простую игру;
- приватный GitHub-репозиторий;
- маленький Telegram-бот;
- папку с `README.md` и файлом правил агента;
- один полезный skill.
