# 03 - Custom MCP

Цель: понять механику "у сервиса есть API - агент может помочь сделать MCP".

Это продвинутый квест. Не начинайте с него, если ещё не делали локальный проект и GitHub.

## Что понадобится

- сервис с публичной API-документацией;
- тестовый API key;
- агент;
- отдельная папка проекта.

## Шаги

1. Выберите простой сервис. Хорошие кандидаты: сервис заметок, todo, календарь, тестовая API-песочница.
2. Создайте отдельную папку.
3. Попросите агента сначала изучить документацию, не писать код.

```text
я хочу сделать MCP для сервиса [название]. сначала изучи публичную документацию API и составь план: какие endpoints нужны, как авторизоваться, какие действия безопасны для первой версии. код пока не пиши.
```

4. Выберите только read-only действие для первой версии.
5. Попросите реализовать минимальный MCP.
6. Протестируйте на тестовых данных.
7. Запишите в README, какие действия поддерживаются и какие права нужны.

## Что проверить

- секреты лежат в `.env`, а не в коде;
- первая версия не удаляет и не изменяет данные;
- MCP возвращает понятную ошибку, если ключ неверный;
- README объясняет установку и ограничения.

## Если сломалось

Сузьте задачу:

```text
оставь только один read-only endpoint. убери все write/delete действия. цель - минимальный рабочий пример.
```
