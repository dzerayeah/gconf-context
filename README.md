# gconf context

Это черновик публичного репозитория с материалами gконф для участников.

Идея репозитория - собрать в одном месте то, что помогает человеку после потока не потеряться: частые вопросы, карту инструментов, практические задания, гайды, команды для агентов и безопасные шаблоны файлов.

Сейчас это не финальная база знаний, а первая структура для ревью. Большинство файлов внутри пока работают как карточки: что можно собрать, из каких уже существующих материалов это берётся и что нужно проверить перед публикацией.

## Для кого

Для участников, которые хотят:

- понять, что вообще поставить и с чего начать;
- разобраться, чем отличаются ChatGPT, Claude, Codex, Claude Code, Cursor и Cowork;
- пройти практические микроквесты;
- собрать свой AI workspace;
- взять готовые команды для агента;
- безопасно работать с GitHub, Railway, Telegram, OpenClaw, Supabase и другими инструментами.

Для команды это репозиторий-сборка: место, где мы превращаем внутренние материалы, Q&A и транскрипты в аккуратные публичные инструкции.

## Статус

`draft`.

Внутри пока не всё написано как готовые инструкции. Часть файлов содержит:

- что именно должно быть в будущем материале;
- реальные источники, из которых его можно собрать;
- что нужно очистить, обновить или не публиковать.

Если вы ревьюите репозиторий, сначала смотрите:

- `STRUCTURE.md` - вся предложенная структура;
- `DO_NOT_INCLUDE.md` - что нельзя тащить в публичную версию;
- `docs/faq.md` - какие вопросы уже можем собрать;
- `microquests/README.md` - как будут устроены практические задания;
- `skills/README.md` - какие команды для агентов уже есть в источниках.

## Что внутри

### `docs/`

Базовая навигация для участника:

- FAQ;
- карта AI-инструментов;
- безопасность, секреты и доступы;
- что делать, если страшно, непонятно или человек застрял.

### `guides/`

Большие гайды, которые можно собрать из уже существующих материалов:

- Claude Code как персональная рабочая среда;
- OpenClaw;
- GitHub;
- Cursor;
- Second Brain.

### `microquests/`

Практические задания потока. Например:

- подключить Telegram MCP;
- сделать простую HTML-игру;
- собрать свой MCP;
- выложить проект на GitHub;
- задеплоить на Railway;
- собрать Telegram-бота;
- попробовать несколько агентов на одну задачу.

Каждый микроквест должен быть коротким и проверяемым: что делаем, что понадобится, шаги, что проверить, что делать если сломалось.

### `skills/`

Готовые markdown-команды для агентов. В v0 это не сложная installable-система, а простые файлы, которые можно скопировать в свой workspace.

Кандидаты уже есть в материалах:

- `daily.md` - собрать фокус дня;
- `coach.md` - короткий коучинговый разговор;
- `content.md` - пост или анонс из сырого материала;
- `tasks.md` - вытащить задачи из текста;
- `meeting.md` - сделать summary созвона;
- `research.md` - провести ресёрч;
- `remind.md` - сделать напоминания о событии;
- `describe-video.md` - собрать описание видео из транскрипта.

### `templates/`

Заготовки файлов, которые участник сможет взять себе:

- `openclaw.env.example`;
- starter для `CLAUDE.md`;
- starter для `AGENTS.md`;
- шаблон напоминаний;
- шаблон описания видео;
- шаблон Q&A summary.

### `events/`

Очищенные конспекты Q&A и важных созвонов. Не raw-транскрипты.

## Правило v0

В эту структуру попадает только то, что уже можно собрать из существующего контента.

Не добавляем разделы по принципу "когда-нибудь было бы полезно". Если у материала нет реального источника в текущей базе, он не попадает в v0.

## Что не публикуем

Не переносим в публичный репозиторий:

- raw-чаты, `.json`, `.txt`, `.srt`;
- токены, `.env`, API keys, Telegram IDs;
- внутренние ссылки на LMS, Zoom, админки и приватные документы;
- имена участников и персональные ситуации без очистки;
- внутренние product-документы команды;
- локальные пути и workspace-инструкции как есть.

Полный список: `DO_NOT_INCLUDE.md`.

## Как довести до публичной версии

1. Выбрать, какие разделы идут в первый релиз.
2. Превратить карточки в нормальные инструкции.
3. Убрать внутренние ссылки, имена, raw-цитаты и локальные пути.
4. Проверить актуальность цен, моделей, лимитов и доступности сервисов.
5. Добавить короткий путь для новичка: "начни здесь".
6. Проверить, что в репозитории нет секретов и персональных данных.
