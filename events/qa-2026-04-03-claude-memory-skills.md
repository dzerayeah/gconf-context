# Q&A 2026-04-03 - Claude, memory, skills

## О чём

Разбор второй недели: чем отличаются Chat, Cowork и Code в Claude, как устроена память, где хранить знания, как использовать skills, как подходить к интеграциям и почему постановка задачи важнее конкретного инструмента.

## Chat, Cowork, Code

Условная карта:

| Режим | Для чего |
|---|---|
| Chat | разговор, идеи, вопросы, тексты |
| Cowork | файлы, контент, интеграции, задачи вокруг рабочего процесса |
| Code | полноценная работа с кодом и проектами |

Cursor ближе к Code. Codex тоже относится к кодинг-агентам.

## Память

Память у моделей не магическая. Надёжный способ - хранить важное в файлах:

- `README.md`;
- `CLAUDE.md` / `AGENTS.md`;
- `notes/`;
- `meetings/`;
- `decisions.md`;
- Obsidian vault, если хочется интерфейс заметок.

Если хотите, чтобы следующий чат что-то знал, попросите текущий чат записать это в файл.

## Skills

Skills, команды, плагины и rules - разные названия одной идеи: повторяемый процесс, упакованный в инструкцию.

Хорошие кандидаты для skills:

- summary созвона;
- вытаскивание задач;
- daily-планирование;
- редактура постов;
- ресёрч;
- проверка проекта перед push.

Сторонние skills надо читать глазами и проверять на вредные инструкции.

## Интеграции

Перед подключением сервиса попросите агента:

```text
изучи документацию сервиса и составь план интеграции. код пока не пиши. отдельно перечисли риски, нужные ключи и минимальную read-only версию.
```

Так меньше шанс, что агент сразу полезет делать слишком сложную или небезопасную интеграцию.

## Excel и CSV

CSV проще для моделей: это структурированный текст.

Excel сложнее: формулы, несколько листов, объединённые ячейки, скрытая логика. Если можно, экспортируйте данные в CSV или просите агента явно проверить формулы и листы.

## Что сделать после

1. Создать свой `CLAUDE.md` или `AGENTS.md`.
2. Взять один skill из `skills/`.
3. Сделать `microquests/06-skills.md`.
4. Начать хранить важное в markdown-файлах, а не в бесконечных чатах.
