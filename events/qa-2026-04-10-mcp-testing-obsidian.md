# Q&A 2026-04-10 - MCP, testing, Obsidian

## О чём

Разбор продвинутых вопросов: как MCP раздувает контекст, когда подключать несколько моделей, зачем тестирование через Playwright, нужен ли OpenClaw, где хранить знания и как подходить к большим проектам.

## MCP и контекст

Каждый подключенный MCP добавляет агенту описание своих возможностей. Если MCP много, контекст становится тяжелее.

Практика:

- включайте только нужные MCP;
- не держите все интеграции активными всегда;
- для каждой интеграции понимайте, что она может читать и менять.

## Несколько моделей

Базово работайте с одним агентом. Если упёрлись в проблему:

1. Попросите текущего агента собрать summary проблемы.
2. Откройте ту же папку в другом агенте.
3. Дайте summary и попросите независимую диагностику.

Это полезно для багов, архитектурных решений и code review.

## Тестирование

Для веб-проектов нужен не только "код написан", а реальная проверка в браузере.

Минимум:

- проект запускается;
- страница открывается;
- основные кнопки работают;
- нет ошибок в консоли;
- мобильная версия не сломана.

Если доступен Playwright, просите агента открывать страницу, делать screenshot и проверять сценарии.

Для ботов проверяйте end-to-end:

- входящее сообщение;
- ответ бота;
- состояние после ответа;
- ошибки и неизвестные команды.

## OpenClaw

OpenClaw полезен, если нужен личный ассистент в Telegram, который работает на сервере. Но это не обязательный инструмент для всех.

Сначала стоит понять:

- нужен ли вам именно ассистент в Telegram;
- готовы ли вы поддерживать сервер;
- есть ли отдельный репозиторий памяти;
- понимаете ли вы, где лежат токены.

## Obsidian и GitHub

Простая формула:

- код - в GitHub;
- знания - в markdown-файлах или Obsidian;
- секреты - в `.env`, не в GitHub;
- большие raw-данные - отдельно, если они не нужны в репозитории.

Obsidian удобен тем, что это локальные markdown-файлы с ссылками между заметками. Агент может читать их как обычные файлы.

## Большие проекты

Агенты могут помогать с большими системами, но начинать всё равно лучше с маленьких модулей.

Рабочий подход:

1. Сделать минимальную версию.
2. Проверить руками.
3. Закоммитить.
4. Добавить один модуль.
5. Снова проверить.

Не просите агента сразу сделать "всё приложение с авторизацией, базой, админкой, платежами и мобильной версией".

## Что сделать после

1. Добавить в свой проект правило: перед выдачей результата проверять через браузер или e2e.
2. Пройти `microquests/12-swarm-agents.md`.
3. Прочитать `guides/second-brain.md`.
4. Проверить, какие MCP у вас включены постоянно и зачем.
