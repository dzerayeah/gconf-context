# Security

Этот репозиторий рассчитан на работу с AI-агентами, GitHub и внешними сервисами. Поэтому главное правило простое: в репозитории не должно быть секретов и приватных данных.

## Никогда не коммитьте

- `.env` с настоящими ключами;
- API keys;
- Telegram bot tokens;
- SSH private keys;
- cookies, session tokens, browser exports;
- клиентские документы и персональные данные;
- приватные ссылки на Zoom, LMS, админки, Notion, Figma, Google Drive;
- raw-экспорты чатов и транскриптов, если там есть имена, usernames, IDs или личные истории.

## Что можно коммитить

- `.env.example` без реальных значений;
- инструкции;
- обезличенные примеры;
- шаблоны;
- короткие тестовые данные, которые вы сами придумали;
- скриншоты и файлы, где нет приватной информации.

## Перед `git push`

Попросите агента проверить репозиторий:

```text
проверь перед push, нет ли в репозитории секретов, .env, токенов, приватных ссылок, персональных данных или raw-экспортов чатов. если что-то нашёл - покажи список файлов и не пушь.
```

Если агент нашёл секрет в истории Git, недостаточно просто удалить файл в новом коммите. Нужно считать секрет скомпрометированным, перевыпустить ключ и очистить историю репозитория.

## Работа с Telegram, почтой и другими MCP

Начинайте с read-only режима, если он доступен.

Для действий вроде отправки сообщений, удаления, архивации, публикации постов или платежей добавляйте явное подтверждение. Хороший минимум:

- allow-list чатов или аккаунтов;
- черновик перед отправкой;
- точная фраза подтверждения, например `отправляй`;
- лог действий в файл.

## Работа с базой данных

Перед любой работой с базой проверьте, что база относится к текущему проекту. Не запускайте миграции, backfill или delete-запросы, пока не понятно:

- какой проект подключен;
- какая среда используется: local, staging или production;
- есть ли backup;
- как проверить результат через продуктовый сценарий.
